## CountUp 数字闪烁 0 的真 bug(用户截图暴露)

**现象**:用户截图显示 **0+ / 0+ / 0 项 / 0 款**,但 curl SSR 返回 48/12500/12/8。

**真因**:CountUp 的修复版 `useState(end)` 初始最终值(SSR 48),但 useEffect IO 触发后**立即 `setCount(0)`**,客户端 hydrate 那一瞬间数字从 48 跳到 0,然后 2 秒动画滚回 48。用户截图若落在 0~100ms 内就看到 0。**之前 agent-browser 实测没看出**是截图时机刚好跳过 0 帧。

**最终修复**:彻底删除 CountUp 动画逻辑,数字直接 `{stat.value.toLocaleString()}` 静态渲染。
- SSR = 客户端 hydrate = 任意时刻,都是最终值,永不变 0
- 适合"简约大气"风格(很多高端网站本身就是静态大数字,动画反而干扰)
- 移除了 useState/useEffect/useRef/useInView/useCallback 等钩子,代码更干净

**验证**:浏览器多次滚动、不同时机检测 `tabular-nums`,始终是 `48+ / 12,500+ / 12 项 / 8 款`,无任何 0 帧。

**教训**:React 客户端动画组件 + SSR 必须严格控制"hydrate 后立即 setState 到不同值"的路径,任何 `setState(初始值 → 其他值)` 都可能产生 0 帧(无论时长多短,自动化截图/SEO/用户截图都可能在那一帧)。要么动画起点 = 当前显示值,要么干脆不动画。
